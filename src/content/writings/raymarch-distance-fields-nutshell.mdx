I keep coming back to raymarching whenever a shape feels easier to describe than to model. A blob, a bevelled box, a repeating tunnel, a logo made from softened primitives: all of those can start as a function before they become a mesh. The danger is that most introductions make the loop feel mystical, so this note keeps the moving parts small enough to debug in one fragment shader.

A signed distance field answers one question: how far am I from the nearest surface, signed so the inside is negative and the outside is positive. March a ray in steps no larger than that distance and you rarely tunnel through thin geometry, which is why the technique loves organic shapes.

```glsl
float map(vec3 p) {
  return length(p - vec3(0.0)) - 1.0; // sphere SDF
}

float trace(vec3 ro, vec3 rd) {
  float t = 0.0;
  for (int i = 0; i < 64; i++) {
    float d = map(ro + rd * t);
    if (d < 1e-3) break;
    t += d;
  }
  return t;
}
```

The live sphere is deliberately plain: no repetition, no soft shadows, no material stack. That is useful because the first failure mode is easy to see. Empty space is cheap; grazing angles and fine filigree are not. Caps on maximum steps, minimum step sizes, and relaxed spheres for shadows are where production shaders spend their complexity budget.

Start with a single primitive you can inspect from every angle, then add only one operator at a time: union, smooth union, mirror, repeat. Composition is the skill; the march loop is mostly bookkeeping once you can tell whether a bug lives in the distance field or in the camera ray.
