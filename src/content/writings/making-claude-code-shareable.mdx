The first time I tried to hand off an agent-heavy debugging session, I shared too much.

There was a long transcript, a branch with a half-fixed bug, and a few commands buried somewhere in the middle that actually mattered. The next person did what any sane engineer would do: ignored most of it and asked me for the short version.

That was the lesson. A shareable Claude Code session is not a transcript dump. It is a handoff note.

```markdown
## Handoff
- Branch: `fix/auth-timeout`
- Tried: raising `idleMs` (no effect on repro)
- Next: inspect refresh token rotation in `auth/refresh.ts`
```

The useful packet is small:

- The branch or PR.
- The exact failing command, if there is one.
- The files that mattered.
- The thing you tried that looked promising but did not work.
- The next bet.

I try to write that while the session is still warm. Waiting until the next morning means I have the transcript but not the shape of the investigation. The model can remember the words; it cannot know which moment made me change direction unless I leave that note.

For commits, I like pulling the high-signal parts into the message: why the fix went this way, what test proved it, and any caveat the next reviewer should not have to rediscover. For a teammate, a short markdown note in the branch is usually enough.

The transcript is still useful as backup. It can answer "what exactly did the agent see?" or "where did that idea come from?" But it should not be the front door. The front door is the curated slice: final patch, failing test name, dead ends, and next step.

Shareable sessions are not raw logs. They are receipts with the noise removed.
