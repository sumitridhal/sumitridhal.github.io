Talos is a **self-owned SDLC control plane**: Work Command Center for operators, talos-runner as the factory kernel, and stage skills that encode triage → ship.

## Problem

Agent demos stall at chat. Shipping needs durable stage commands, isolated workers, ledgers, and a UI that shows where work sits in the lifecycle — without outsourcing control to a hosted orchestration SaaS.

## Approach

- **`apps/work-command-center`** — Next.js UI (default `:3200`).
- **`apps/talos-runner`** — factory kernel with CLI adapters, workers, ledger (`:4111`).
- **`vendor/sdlc-skills`** — stage commands and skill packs (source of stage behavior).
- **Lifecycle:** triage → spec → plan → build → simplify/test → review ⇄ resolve-conflicts → verify → ship → release (+ learn).
- **Docs:** capability suite under `docs/` for operators; ADRs and factory-phases remain the decision record.

## Tech stack

Next.js Command Center, talos-runner, Cursor/Claude CLI adapters, vendor skill packs. Legacy `apps/mastra-sdlc` is replaced and should not be started.

## Demo

```bash
cd ~/git/talos
cd apps/talos-runner && npm install && npm run dev          # :4111
cd apps/work-command-center && npm install && npm run dev   # :3200
# Set DEMO_TOKEN in WCC .env.local when auth is enabled
```
